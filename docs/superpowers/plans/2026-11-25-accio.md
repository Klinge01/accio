# accio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** macOS menu-bar RAG chatbot over user-chosen folders (md/pdf/office/images) with Groq streaming answers, optimized for lowest latency.

**Architecture:** One resident Tauri v2 process: Rust core (`accio-core`) owns SQLite (FTS5 + f16 vectors), in-RAM binary-quantized vector index, fastembed-rs embedder/reranker, Groq streaming client, ingestion manager. A stateless Python worker (`accio-ingest serve`) is spawned only during ingestion jobs and turns files into chunks over JSON lines. Webview UI renders streamed markdown (KaTeX, mermaid, highlight.js).

**Tech Stack:** Rust 1.99, Tauri 2 (+ plugins global-shortcut, dialog, opener), rusqlite (bundled), fastembed, half, ignore, globset, blake3, reqwest (http2, rustls, stream), tokio; Python 3.12 via uv: pymupdf4llm, markitdown, pyobjc-framework-Vision/Quartz, mlx-vlm, Pillow; UI: TypeScript, Vite, vitest, markdown-it, katex, mermaid, highlight.js.

**Spec:** `docs/superpowers/specs/2026-11-25-accio-design.md`

## Global Constraints

- Hotkey `Alt+Space` (⌥Space). App has no Dock icon (`ActivationPolicy::Accessory`).
- API key from `.env` (`GROQ_API_KEY`); load repo-root `.env`, then `$ACCIO_HOME/.env` overrides.
- `ACCIO_HOME` default `~/Library/Application Support/accio/`; tests always set it to a tempdir.
- Default model `openai/gpt-oss-20b`, `reasoning_effort: "low"`, `include_reasoning: false`, `max_completion_tokens: 2048`.
- Embedding dim 512 (EmbeddingGemma300M, Matryoshka-truncated, re-normalized); vectors stored as little-endian f16 blobs.
- Retrieval constants: dense top 50 from 200 Hamming candidates; FTS top 50; RRF k=60; rerank top 20; τ=0.2 (sigmoid); max 6 chunks.
- Chunker: max 1800 chars, min 200 chars, split at H1–H3, fenced/`$$` blocks atomic.
- Per-file parse timeout 300 s. One ingestion job at a time, FIFO.
- No automatic ingestion except immediately after "Add folder…".
- Python pinned `>=3.12,<3.13` (pyobjc/mlx wheels); never run under the system 3.14.
- All Rust DB writes go through `Store`; Python never touches the DB.

## Implementation and verification

The files for Tasks 1–13 are in the workspace. Implementation checkboxes are marked below. Git initialization was blocked by workspace permissions. Missing registry dependencies and loopback access blocked the full test suites and native acceptance run.

The 200-candidate Hamming shortlist follows design spec §4. The release benchmark averaged 1.10 ms per search at 150,000 vectors. The independent random-vector test measured 67.6% recall@10 against brute force, below the planned 90% target. A separate regression checks recall on clustered vectors. The eval tool measures retrieval modes against indexed notes and a question set.

Ingestion pins the published vectors, FTS, and chunk data to one SQLite snapshot. It checks the backing volume before deletions and puts filesystem reads under a per-file timeout in a Rust child process. Eval opens the index read-only.

## Review Focus

1. **Source folder missing/unmounted** (e.g. a cloud-synced vault offline) → re-ingest must fail with `folder not found: <path>` and delete nothing. Test in Task 7.
2. **Parser hangs or crashes on one file** (encrypted/corrupt PDF, cloud placeholder file) → that file fails with `timeout after 300s`/`worker crashed`, worker respawns, job continues. Test in Task 8 (timeout shortened via config).
3. **Query text with FTS5 syntax** (`"`, `-`, `*`, `:`, `NEAR`, `C++`, `AND`, empty) → no SQL error, sanitized search. Test in Task 5.
4. **Groq failure modes** (no key, 401, 429, stream drop mid-answer) → readable error text in panel, app keeps working. Tests in Task 10.
5. **Re-ingest requested while a job runs / query during ingest** → no duplicate job, queries keep answering from old index. Test in Task 8.
